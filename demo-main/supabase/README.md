# Supabase backend (RehabTrack)

Everything the online mode needs: one migration, a seed with relative dates, one Edge Function, and a local test.
The web app works without any of this (offline LocalSource is the default). Supabase mode turns on when
`VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are set in `demo-main/web/.env.local`.

| Path | What it is |
|---|---|
| `migrations/0001_init.sql` | 9 tables, RLS (demo public read), write RPCs, `replays` Storage bucket + policies. Safe to re-run. |
| `seed.sql` | 3 demo patients (`p-maria`, `p-james`, `p-priya`), ~3 weeks of data relative to **today**. Deletes and re-creates them. Generated by `web/scripts/gen-seed-sql.ts` (`npm run seed:sql`). |
| `functions/weekly-summary/index.ts` | Edge Function: two-sentence therapist summary from Gemma, stored with `upsert_summary`. |
| `tests/pglite-smoke.mjs` | Applies migration + seed in PGlite (in-process Postgres) and checks every RPC. `cd web && npm run db:test`. |
| `config.toml` | Minimal CLI config. |

## 1. Apply the schema and seed

### Option A: SQL Editor (no tools needed)
1. Create a project at https://supabase.com (free tier is fine).
2. **SQL Editor** → New query → paste all of `migrations/0001_init.sql` → **Run**.
3. New query → paste all of `seed.sql` → **Run**.
4. **Project Settings → API**: copy the **Project URL** and the **anon public** key into `demo-main/web/.env.local`:
   ```
   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
   VITE_SUPABASE_ANON_KEY=<anon public key>
   ```

### Option B: Supabase CLI
```sh
cd demo-main
supabase link --project-ref <project-ref>
supabase db push                                   # applies migrations/0001_init.sql
psql "$(supabase db url)" -f supabase/seed.sql      # or paste seed.sql in the SQL Editor
```
(`supabase db reset` against a local stack applies the migration and `seed.sql` together.)

**Re-run `seed.sql` on the morning of the demo.** All dates are relative to the day it runs, and today is left
empty for the live session. Re-running deletes only the three demo patients (cascade) and re-creates them.

## 2. Edge Function `weekly-summary` (optional, stretch)

```sh
cd demo-main
supabase secrets set GOOGLE_API_KEY=<key from Google AI Studio>
supabase secrets set ALLOWED_ORIGIN=https://<your-app>.vercel.app,http://localhost:5173
# optional: supabase secrets set GEMMA_MODEL=gemma-4-26b-a4b-it
supabase functions deploy weekly-summary
```
- Input `POST {patientId}`; output a `WeeklySummary` (`{patientId, weekStart, text, model, source: 'llm', createdAt}`).
- Uses the service-role key that Supabase injects into Edge Functions. Never put the service-role key in the web app.
- Calls the same Gemma model chain as Stuti's proxy, retries once on 429/5xx. Repeated calls within 60 s return
  the stored summary instead of calling Gemma again.
- The prompt forbids diagnosis, plan advice and invented numbers. Pre-generated summaries from `seed.sql` mean
  the card always has text even if the function is never deployed.

## 3. Data access model (DEMO ONLY)

- **Reads:** `anon` and `authenticated` can `select` every table (`demo_read` policies). The data is fake.
  Replace these policies with real auth before any real patient data.
- **Writes:** no direct table writes. Only these `SECURITY DEFINER` RPCs (all `search_path = ''`):

| RPC | Called by | Body / arguments |
|---|---|---|
| `submit_watch_daily` | iPhone Shortcut, demo panel | raw body `{patientId, date, steps?, exerciseMin?, standHr?, restingHr?, hrv?, sleepHr?, bpSys?, bpDia?, falls?, walkingSteadiness?, weakArmActiveMin?, useRatio?}`. **Merge:** omitted/blank fields (and 0 for restingHr, hrv, bpSys, bpDia, walkingSteadiness) keep the old value |
| `submit_watch_session` | watch app | raw body, see `docs/SHORTCUT.md` / `watch/README.md` |
| `submit_session` | patient app | raw body `SessionUploadBody` (idempotent on `clientKey`) |
| `register_replay` | patient app | raw body `{sessionId, exercise, side, path, fps, frameCount, seconds, warningCount}` |
| `apply_rule_results` | rules engine (browser) | `{p_patient_id, p_alerts, p_plan}` |
| `ack_alert` | care | `{p_alert_id}` |
| `approve_plan` | care | `{p_plan_id, p_approved_by, p_overrides}` |
| `dismiss_plan` | care | `{p_plan_id, p_dismissed_by}` |
| `save_plan` | care | `{p_patient_id, p_plan, p_approved_by}` |
| `set_next_checkin` | care | `{p_patient_id, p_date}` |
| `upsert_summary` | Edge Function only (`service_role`) | `{p_patient_id, p_week_start, p_text, p_model}` |

"Raw body" RPCs have a single unnamed `jsonb` parameter, so PostgREST passes the whole request body: the Shortcut and
the watch post the contract JSON as-is to `/rest/v1/rpc/<name>`.

Errors: `PT400` → HTTP 400 (invalid input, friendly message), `PT404` → 404 (`Unknown patient` etc.),
`PT409` → 409 (wrong plan state, sessionId owned by another patient). CHECK violations (out-of-range numbers)
come back as Postgres error `23514`.

- **Storage:** bucket `replays`, public read, 2 MB, `application/json`. Uploads (insert/update) are allowed only into
  a folder named after a session created in the last 24 h: `replays/<sessionId>/<exercise>-<side>.json`.
- **Realtime:** not used (the app polls every 5 s).
- Anyone with the anon key can call the RPCs (including approving plans). Acceptable for fake data; rotate the anon
  key after the event.

## 4. Test locally (no Supabase project needed)

```sh
cd demo-main/web && npm install && npm run db:test
```
Runs the migration twice and the seed twice in PGlite with stub `anon`/`authenticated`/`service_role` roles and a stub
`storage` schema, then checks: idempotent `submit_session`, watch merge, unknown patient → PT404, NaN rejected,
`approve_plan` supersedes and mirrors phase, duplicate open alerts ignored, `save_plan` dismisses the suggestion,
storage folder policy, grants, and that every function pins `search_path`.

## 5. Regenerate the seed

```sh
cd demo-main/web && npm run seed:sql
```
Writes `supabase/seed.sql` from `web/src/data/seed/generate.ts` (the same generator the offline mode uses), so both
modes show the same story. Two runs on the same day produce identical files.
